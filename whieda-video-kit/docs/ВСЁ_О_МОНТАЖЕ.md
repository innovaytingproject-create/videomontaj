- Пользователь присылает ссылки Google Drive (часто несколько частей «10.1, 10.2…»)

## 3. Утверждённый стиль «WHIEDA v3»

Всё зашито в `template/style.css` и `pipeline/build.py` — не перерисовывать.

**Картинка.** Ярко, насыщенно, чисто: шумодав + яркость + насыщенность + лёгкая
S-кривая + резкость (фильтр `GRADE` в `prepare.py` и во всех `cut.py`). Не «кино»,
не холодный Apple.

**Субтитры.** Gilroy ExtraBold 62 px, белые, **только тени** (без подложки и обводки),
на уровне груди (bottom 860 px), фразы по 2–6 слов, слова всплывают по одному.
Одно ключевое слово на фразу — акцент `*слово*`:
- синий `#0A84FF` по умолчанию;
- **красная / синяя / тёмная одежда → `"caption_accent": "#9FD0FF"`** (светло-голубой);
- на белой блузке синий читается (тени спасают) — проверять по кадру.

**Вставки над головой (верх 140–330 px):** обложка `cover`, уведомление iOS `banners`,
плашки-«таблетки» `pills` (галочка или белая иконка), пузыри `bubbles` (до 3),
плашка-логотип WHIEDA `logos` — ровно когда говорят «WHIEDA / assotsiatsiya».

**Белая карточка-акцент** раз в ~15 с: тонкая серая строка + крупное слово с синим
акцентом (`cards`, `|` — перенос, `"numeric": true` для чисел, можно синюю иконку).
Во время карточки субтитров нет — карточка закрывает кадр, голос идёт.

**Камера.** Каждые ~7 с наезд/отъезд с переходом (рывок масштаба + поворот + размытие +
вспышка). Если есть склейки — ставь переходы **на склейки** (`"transitions": [...]`),
они прячут прыжок между дублями.

**Световые эффекты — мягко (правка клиента 13.10: «слишком много световых эффектов,
напрягает»).** Для всех новых роликов ставь
`"fx": {"flash": 0.25, "tint": 0.4, "blur": 8, "rot": 1.5}`;
ещё мягче — `{"flash": 0.18, "tint": 0.3, "blur": 6, "rot": 1.2}` (ролик «3 привычки»).
Без `fx` — старая сильная версия (вспышка 0.6, синий отсвет 1, размытие 18).

**Конец.** Карточка с эмблемой WHIEDA, подпись `WHIEDA · Feruza Sabitova` и синяя
кнопка-призыв (`end_card.pill`, например «Direktga yozing: «Sauna»»). +1.8 с.

**Звук.**
- Голос — главный: шумодав, компрессор, итог **−13…−14 LUFS** (проверка `ebur128`).
- Музыка `chronos` (или `advertime`) тихо, уходит под голос (ducking), слышна в паузах.
- Саунд-дизайн автоматически: whoosh+boom на переходах, boom на карточках, pop на
  логотипе/иконках/пузырях/стикерах, tick на плашках, ding на уведомлении, riser в
  финале. Дополнительно — поле `sfx`.

**Бренд.** Палитра Ферузы: #FFFFFF, #F5F5F7, #EAF3FF, #BFD9FF, акцент #0A84FF, текст
#1D1D1F. WHIEDA: Montserrat, эмблема красно-оранжевая, слово «WHIEDA» янтарное #BA7A08.
Брендбуки — `docs/brandbooks/`.

## 5. Монтаж: что можно резать, а что нельзя

- **Паузы между фразами можно вырезать** (динамика) — это одобрено во всех роликах.
- **Нельзя резать и ускорять действия:** проходы, где она идёт и говорит, показ
  товара, распаковку, демонстрацию. (Правка 13.10 по «3 привычкам»: «не нравится, что
  обрезал, где она ходит и говорит» — проход вернули целиком в обычной скорости.)
- **Ускорение речи 1.2–1.25×** — только для длинных товарных монологов, где она
  быстро и ровно говорит (FOHERB, стельки 1.25×; активатор 1.2×). Для блога — нет.
- Невнятную или повторную фразу можно убрать, но **сказать об этом пользователю**.
- Посторонний шум (работающий прибор, фен) — найти по спектрограмме и вырезать или
  приглушить (см. 6.4). Правка 12.10: «звук прибора раздражает».
- Если файл назван «… (и отдельно)» — эта часть идёт и в общий ролик, **и отдельным
  коротким роликом** (пример: `archive/video15b`). Итого два ролика.

## 6. Приёмы (как это делается технически)

### 6.1 Несколько частей → один ролик
Склеивать через фильтр `concat` (он учитывает поворот айфона, -90°):
```
ffmpeg -i p1.mov -i p2.mov … -filter_complex "[0:v]setsar=1,fps=30[v0];[1:v]…;[v0][0:a][v1][1:a]…concat=n=N:v=1:a=1[v][a]" \
  -map "[v]" -map "[a]" -c:v libx264 -crf 12 -preset fast -pix_fmt yuv420p -c:a pcm_s16le -ar 48000 work/joined.mov
```
Дальше — свой `work/cut.py`: список кусков `K=[(начало, конец), …]` в секундах
`joined.mov`, каждый второй кусок чуть приближен (1.09×) — это прячет склейки;
затем покраска `GRADE` и голос `VOICE`. Образцы: `archive/video15/cut.py` (паузы),
`archive/video13/cut.py` (перестановка + перебивки + ускорение),
`archive/video11/cut.py` (разная скорость кусков).

### 6.2 Расшифровка
- Модель `large-v3`, язык **`uz`** всегда.
- Длинное видео из частей — **расшифровывать каждую часть отдельно** с
  `condition_on_previous_text=False`, иначе whisper «слипается» и теряет целые куски.
- Если `faster_whisper` падает на PyAV — подавать numpy-массив (wav 16 кГц через ffmpeg).
- Части без речи (whisper выдаёт «Субтитры сделал…», «Продолжение следует…») —
  это немая демонстрация → перебивки.
- Вычитывать вручную: whisper пишет «VEDA/MEDA» вместо **WHIEDA**, путает узбекский.
  Сомневаешься в слове — пиши проще и короче, но не выдумывай.

### 6.3 Перебивки (B-roll) поверх голоса
Немые кадры демонстрации кладутся **поверх видео**, голос идёт дальше:
`overlay=enable='between(t,a,b)'` по таблице `BR=[(время голоса, начало перебивки, длительность)]`
— см. `archive/video13/cut.py`. Выбирай перебивку по смыслу слов (волосы → «выпадают
волосы», рука → «пятна», по телу → «по всему телу»).

### 6.4 Посторонний шум
Спектрограмма: `ffmpeg -i f -lavfi showspectrumpic=s=2400x300:legend=0:fscale=lin:stop=6000 sp.png`.
Шум прибора — горизонтальные полосы (тон ~372 Гц + гармоники) или широкая «стена».
Найти время по уровню 6–12 кГц, вырезать кусок или приглушить.

### 6.5 Времена в project.json
Все времена — **секунды готового `work/video.mp4`** (после нарезки и ускорения).
Перевод из исходника: функция `m(t)` по списку кусков (см. любой `cut.py` / скрипт в
архиве), при ускорении — делить на скорость.

### 6.6 Частые ошибки проверки (`hyperframes check`)
- `content_overlap … #elogo` — последний субтитр/плашка залезает на финальную
  карточку: конец ≤ `длительность_видео − 0.75`.
- `content_overlap` субтитра с карточкой — субтитр попал под карточку, сдвинуть.
- Предупреждения ⚠ (overlapping tweens, contrast у обложки) — норма.

### 6.7 Место на диске
Промежуточные `work/joined.mov`, `work/seg/`, `out/pic.mp4` можно удалять после
сдачи — всё пересоздаётся из исходника и `cut.py`. Исходник всегда можно скачать
заново по ссылке (таблица в разделе 8).

## 9. Сдача готового ролика

1. `out/<проект>.mp4` — полное качество (Instagram).
2. `python3 pipeline/compress.py projects/<проект>/out/<проект>.mp4 28` →
   `<проект>-small.mp4` (до 28 МБ, для Телеграма / просмотра).
3. На GitHub — ветка `gotovye-video`, новая папка `ГОТОВЫЕ_ВИДЕО/<№>_<Название>_<длина>`.
   Файлы > 90 МБ резать: `split -b 94371840 -d -a 2 --numeric-suffixes=1 файл.mp4 папка/Имя.mp4.part`
   (склеивают `СОБРАТЬ_ВИДЕО_*.sh/.bat` в корне ветки). Переделанный ролик — заменить
   файлы в его папке и поправить длительность в названии.
4. Если push падает с ошибкой сервера — повторить через 2, 4, 8, 16 с.

## 10. Команды (шпаргалка)

```
python3 pipeline/new_project.py <имя> "<ссылка Drive>"     # скачать (одна часть)
python3 -m gdown <ID> -O projects/<имя>/source/            # каждая следующая часть
python3 pipeline/prepare.py <имя>                           # одна часть целиком без вырезок
python3 pipeline/transcribe.py <имя> --lang uz              # расшифровка (одна часть)
#   несколько частей / вырезки → свой work/cut.py (раздел 6)
python3 pipeline/build.py <имя>                             # собрать index.html из project.json
cd projects/<имя> && npx --yes hyperframes@0.8.137 check    # проверка (0 ошибок)
npx --yes hyperframes@0.8.137 render --quality looks --output out/pic.mp4
cd ../.. && python3 pipeline/mix.py <имя>                   # звук → out/<имя>.mp4
python3 pipeline/compress.py projects/<имя>/out/<имя>.mp4 28
```
Проверка результата: длительность (`ffprobe`), громкость (`ffmpeg -af ebur128`, около −13…−14),
кадры каждые 3–5 с (`ffmpeg -ss t -frames:v 1`) — субтитры, карточки, стикеры, конец.
